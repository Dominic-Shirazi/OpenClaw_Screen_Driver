# Phase 4 — UI Design Contract

> Visual and interaction contract for the recording flow. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (PyQt6 desktop overlay — not a web app) |
| Preset | not applicable |
| Component library | QGraphicsObject scene items (established Phase 1-3 pattern) |
| Icon library | none — text-only toolbar buttons, no icon assets |
| Font | Segoe UI on Windows, system sans-serif fallback on Linux/macOS |

Source: `recorder/overlay/hud_common.py` — established Phase 3 tokens.

## Spacing Scale

Declared values (all multiples of 4), inherited from `hud_common.SPACING`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, field internal padding |
| sm | 8px | Compact element spacing, button gaps in toolbar |
| md | 16px | Default element spacing, panel internal padding |
| lg | 24px | Section padding, toolbar offset from screen edge |

Exceptions:
- Countdown widget offset from cursor: 20px (not a multiple of 4 — acceptable for cursor tracking where pixel-precision alignment is irrelevant)
- Countdown widget diameter: 52px (circle that contains the countdown digit with breathing room)

Source: `hud_common.SPACING` SimpleNamespace, established Phase 3.

## Typography

All values inherited from `hud_common.py` — no new font sizes introduced in Phase 4.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Helper tips | 10px | 300 (light) | 1.4 |
| Labels / toolbar buttons | 12px | 400 (regular) | 1.4 |
| Input text / section headings | 14px | 400 (regular) | 1.5 |
| Countdown digit | 28px | 300 (light) | 1.0 |

The countdown digit at 28px is the only new typographic element in Phase 4. It uses the same font family (Segoe UI / system sans-serif) and light weight to match the overlay's thin-font aesthetic.

Source: `hud_common.FONT_SIZE_*` and `FONT_WEIGHT_*` constants.

## Color

All colors inherited from Phase 1-3 design system. Phase 4 introduces no new color values.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Transparent (overlay is fully transparent) | Full-screen overlay background — user sees desktop through it |
| Secondary (30%) | `rgba(15, 15, 25, 200)` — FROST_BG | Tag dialog panel, abort confirmation panel, countdown widget background |
| Accent (10%) | `rgba(50, 200, 50)` — ACCENT_GREEN | Confirm button fill, success flash, card glow border, countdown digit color |
| Recording state | `rgba(255, 50, 50)` — STATE_COLORS[RECORDING] | Shimmer glow during recording, scan animation, bbox border |
| Destructive | `rgba(255, 50, 50, 200)` — same as recording red | Abort confirmation "Discard" button highlight |

Accent reserved for:
- Confirm/Yes button background (`CONFIRM_BG`)
- Success flash after dry-run validation (500ms green pulse)
- Card glow underglow on tag dialog and countdown widget
- Countdown digit text color
- Toolbar "Yes" button in VALIDATING mode

Recording red reserved for:
- Shimmer border during RECORDING state
- Scan animation elements
- Bbox border during editing
- Toolbar "Retry" button accent
- "Discard" button on abort confirmation

Source: `hud_common.py` color constants, `state.py` STATE_COLORS.

## New Visual Elements (Phase 4)

### Countdown Widget

| Property | Value |
|----------|-------|
| Shape | Circle, 52px diameter |
| Background | `FROST_BG` with frosted glass blur (matches tag dialog aesthetic) |
| Border | 1px `BORDER_SUBTLE` (green at 60 alpha) |
| Digit | 28px, weight 300, `ACCENT_GREEN` color |
| Position | Follows mouse cursor with 20px x-offset and 20px y-offset from cursor tip |
| Z-value | 300 (above all other overlay elements) |
| Corner radius | 26px (half of 52px = perfect circle) |
| Card glow | Optional thin underglow using `paint_card_glow()` from hud_common |
| Animation | Digit shrinks from 1.0 to 0.7 scale and fades from 230 to 0 alpha over 800ms, then snaps to next digit at full scale/alpha |
| Finish signal | Emits `countdown_finished` pyqtSignal after final tick |

### Validation Toolbar Mode

A new `ToolbarMode.VALIDATING` mode added to the existing toolbar:

| Property | Value |
|----------|-------|
| Buttons | `Yes` / `Edit Tags` / `Re-capture` / `Retry` |
| Button style | Same pill buttons as existing toolbar modes (frosted glass, 12px label weight 400) |
| `Yes` button | Green accent background (`CONFIRM_BG`) — matches tag dialog confirm |
| `Edit Tags` button | Default button style (`DISMISS_BG`) |
| `Re-capture` button | Default button style (`DISMISS_BG`) |
| `Retry` button | Default button style (`DISMISS_BG`) |

### Success Flash

| Property | Value |
|----------|-------|
| Duration | 500ms total |

| Color | `ACCENT_GREEN` at alpha 120, fading to alpha 0 over 500ms |

| Position | Centered on screen |

## Interaction States

### RecordPhase Sub-State Machine

Each sub-state maps to specific visual and interaction behavior:

| RecordPhase | Shimmer | Cursor | Click Behavior | Toolbar Mode | Active Panels |
|-------------|---------|--------|----------------|--------------|---------------|
| AWAITING_CLICK | Red (recording) | Crosshair | Captured by overlay | RECORDING | None |
| CAPTURING | Hidden (capture cycle) | System default | Pass-through | Hidden | None |
| DETECTING | Red (recording) | Wait/busy | Blocked (ignored) | RECORDING | Card glow pulsing |
| BBOX_EDITING | Red (recording) | Resize on handles, crosshair elsewhere | Handles draggable, double-click accepts | RECORDING | Bbox with handles |
| VLM_ANALYZING | Red (recording) | Wait/busy | Blocked (ignored) | RECORDING | Card glow pulsing |
| TAG_DIALOG | Red (recording) | Text cursor in fields | Field interaction | TAG_OPEN | Tag dialog panel |
| COUNTDOWN | Red (recording) | Free movement | Blocked (ignored) | DRY_RUN | Countdown widget follows cursor |
| EXECUTING | Red (recording), click-through ON | System default | Pass-through to desktop | DRY_RUN | Shimmer visible but non-interactive |
| VALIDATING | Red (recording) | Arrow | Toolbar button clicks | VALIDATING | Toolbar with Yes/Edit/Re-capture/Retry |
| SUCCESS_FLASH | Red (recording) | None (brief) | Blocked (500ms) | None | Bbox green flash |

### Bbox Acceptance Flow

1. AI bbox appears with morph animation (existing scan_layer -> bbox_layer)
2. Handles appear on bbox corners and edges
3. User can drag handles to adjust bbox
4. Double-click bbox OR press Enter to accept
5. If drag-highlight capture: user can press Escape to revert to original drag rect

### Abort Flow

1. User presses ESC
2. If zero steps captured: close overlay silently, no confirmation
3. If one or more steps captured: show abort confirmation panel (centered)
4. "Discard" closes overlay, discards all in-memory session data
5. "Keep Recording" dismisses panel, returns to AWAITING_CLICK
