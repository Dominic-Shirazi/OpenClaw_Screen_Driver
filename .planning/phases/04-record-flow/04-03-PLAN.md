**1. Create `recorder/platform_utils.py`:**

```python
"""Cross-platform utility functions for recording flow."""
from __future__ import annotations
import logging
import sys
import time

logger = logging.getLogger(__name__)

def minimize_all_windows() -> bool:
    """Minimize all windows to show desktop (Win+D equivalent).
    Returns True if successful, False if platform not supported or failed."""
    if sys.platform != "win32":
        logger.warning("Window minimize only supported on Windows currently")
        return False
    try:
        import ctypes
        VK_LWIN = 0x5B
        VK_D = 0x44
        KEYEVENTF_KEYUP = 0x0002
        user32 = ctypes.windll.user32
        user32.keybd_event(VK_LWIN, 0, 0, 0)
        user32.keybd_event(VK_D, 0, 0, 0)
        user32.keybd_event(VK_D, 0, KEYEVENTF_KEYUP, 0)
        user32.keybd_event(VK_LWIN, 0, KEYEVENTF_KEYUP, 0)
        time.sleep(0.5)  # Wait for minimize animation
        return True
    except Exception as e:
        logger.warning("Failed to minimize windows: %s", e)
        return False
```

**2. Create `recorder/record_session.py`:**

Class `RecordSession` that orchestrates the full recording pipeline. Key design:

**Constructor:**
```python
class RecordSession:
    def __init__(self, controller: OverlayController, routine_name: str, start_from: str = "desktop") -> None:
```
- `controller`: OverlayController instance (already created by record_flow.py)
- `routine_name`: validated name from TUI prompt
- `start_from`: "desktop" or "app"
- Creates `PipelineBridge` instance
- Connects bridge signals to handler methods
- Initializes `self._phase = RecordPhase.AWAITING_CLICK`
- Initializes `self._steps: list[dict] = []` (accumulated recorded steps)
- Initializes `self._current_step: dict | None = None` (step being built)
- Initializes `self._current_bbox: tuple[int, int, int, int] | None = None`
- Initializes `self._original_drag_rect: tuple[int, int, int, int] | None = None` (for drag undo)
- Initializes `self._screenshot: np.ndarray | None = None` (current clean capture)

**Public methods:**
- `start() -> None`: Wires the controller callbacks (on_selection, on_state_changed, on_save, on_abort), shows toolbar in RECORDING mode, transitions to AWAITING_CLICK
- `on_selection(x: int, y: int, w: int, h: int) -> None`: Main entry from overlay click/drag. Determines click vs drag, sets phase to CAPTURING, runs capture pipeline
- `on_toolbar_action(action: str) -> None`: Routes toolbar button clicks to handlers (yes, edit_tags, recapture, retry, confirm, dismiss, pause, undo_last, run_step, etc.)
- `on_tag_confirmed(data: dict) -> None`: Tag dialog confirmed -- store step data, transition to COUNTDOWN
- `on_tag_dismissed(data: dict) -> None`: Tag dialog dismissed -- discard step, back to AWAITING_CLICK
- `on_save_requested() -> None`: Ctrl+Q handler -- save all steps
- `on_abort_requested() -> None`: ESC handler -- show abort confirm or close silently
- `step_count -> int`: Property returning len(self._steps)

**Private pipeline methods:**

`_run_capture_pipeline() -> None`:
1. Set phase to CAPTURING
2. `controller.hide_for_capture()`
3. `time.sleep(config.get("overlay", {}).get("capture_delay_ms", 80) / 1000)` -- DWM flush
4. Take screenshot: `screenshot_full()`
5. `controller.show_after_capture()`
6. Set phase to DETECTING
7. Start background detection thread

`_start_detection(screenshot: np.ndarray, click_x: int, click_y: int, is_drag: bool) -> None`:
Run in `threading.Thread(daemon=True)`. Cascade detection:
- If click (not drag): click-local crop (~120px radius), run detector.detect(crop), offset results to screen coords. If no result, run detector.detect(full_screenshot).
- If drag: run `_try_refine_bbox` IoU logic from record_controller (adapted inline).
- Emit `self._bridge.detection_ready.emit(result_dict)` with `{bbox: {x,y,w,h}, type_guess, florence_caption, candidates}`.
- If no detection found: emit with bbox=None.

`_on_detection_ready(result: dict) -> None` (connected to bridge signal, runs on main thread):
1. If result has bbox: show scan animation via `controller.start_scan()`, then `controller.finish_scan()` after short delay. Set phase to BBOX_EDITING.
2. If no bbox found: use click position as center, create a default 60x60 bbox. Transition directly to VLM_ANALYZING.
3. Store `self._current_bbox` and enable bbox editing on the bbox layer.

`_accept_bbox() -> None`:
1. Read final bbox from bbox layer (possibly user-edited)
2. Set phase to VLM_ANALYZING
3. Start VLM thread

`_start_vlm(screenshot: np.ndarray, bbox: tuple[int, int, int, int]) -> None`:
Run in `threading.Thread(daemon=True)`:
1. Compute 30% padded crop from screenshot using bbox coords
2. Call `analyze_crop_array(crop)` with 15s timeout
3. If success: emit `self._bridge.vlm_ready.emit(result)`
4. If timeout/error: retry once with 8s timeout
5. If still fails: emit `self._bridge.vlm_failed.emit(error_msg)`

`_on_vlm_ready(result: dict) -> None`:
1. Set phase to TAG_DIALOG
2. Build vlm_data dict: `{element_type, label_guess, confidence, ocr_text, caption}`
3. Show tag dialog: `controller.show_tag_dialog(element_rect, vlm_data=vlm_data)`
4. Set toolbar mode to TAG_OPEN

`_on_vlm_failed(error: str) -> None`:
1. Set phase to TAG_DIALOG
2. Show tag dialog with partial data: `controller.show_tag_dialog(element_rect, vlm_data=partial_data)`
3. Log VLM failure. The tag dialog helper text will show "VLM unavailable" per UI-SPEC.
4. Set toolbar mode to TAG_OPEN

`_set_phase(phase: RecordPhase) -> None`:
Private method that updates `self._phase` and logs the transition. This is where future visual state syncing (cursor changes, toolbar mode) can be centralized.

**State transition rules (enforced in on_selection):**
- Only accept new selections when phase is AWAITING_CLICK
- Ignore clicks in all other phases (prevents race condition per RESEARCH pitfall 5)

**Toolbar action routing:**
- "confirm" (from TAG_OPEN): call `on_tag_confirmed(controller.get_tag_data())`
- "dismiss" (from TAG_OPEN): call `on_tag_dismissed(controller.get_tag_data())`
- "yes" (from VALIDATING): lock step, flash success, return to AWAITING_CLICK
- "edit_tags" (from VALIDATING): reopen tag dialog with edit_mode=True
- "recapture" (from VALIDATING): discard current step, return to AWAITING_CLICK
- "retry" (from VALIDATING): re-run countdown + dry-run

(Note: COUNTDOWN, EXECUTING, VALIDATING wiring is Plan 04. This plan wires up to TAG_DIALOG.)
