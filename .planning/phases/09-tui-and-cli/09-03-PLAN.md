  <action>
    **Add variable collection to cli/output.py:**

    Add function `collect_variables(routine_dir: Path, provided_params: dict[str, str]) -> dict[str, str]`:
    - Load routine via `Routine.load(routine_dir)`.
    - Scan `routine.steps` for steps where `step.get("input_spec", {}).get("type") == "variable"`.
    - For each variable step, extract `var_name` by stripping `{` and `}` from `input_spec["value"]`. Extract `hint` from `input_spec.get("hint", f"Enter {var_name}")`.
    - If `var_name` already in `provided_params`, skip prompting.
    - For missing variables, prompt via `rich.prompt.Prompt.ask(f"[bold]{hint}[/]")`.
    - Return merged dict of all params.

    Add function `inject_variables(routine_dir: Path, params: dict[str, str]) -> None`:
    - Load routine, iterate steps, for each step with `input_spec.type == "variable"`, resolve the value from `params` and set `step["text_to_type"] = resolved_value`.
    - Save routine back (this modifies in-memory only for the run, NOT saved to disk -- work on a copy).
    - Actually, better approach: return a modified steps list without saving. Or better yet, just return the params dict and let the runner handle it.
    - Decision: Don't modify steps. Instead, the `collect_variables` function returns the complete params dict. The CLI `run` command will need to pass these as `execution_params` to the runner. Since `run_routine()` doesn't accept `execution_params`, pre-process the steps in a temporary copy before calling `run_routine()`. Use `_resolve_input_text` pattern from `mapper/runner.py`.

    Revised approach -- add `prepare_routine_for_run(routine_dir: Path, params: dict[str, str]) -> None`:
    - Load routine from `routine_dir`.
    - For each step with `input_spec.type == "variable"`, resolve the variable from `params` dict and set `step["text_to_type"]` to the resolved value.
    - Save the modified routine back to a TEMPORARY location (copy to `routine_dir / ".run_staging" / "routine.json"`).
    - Return the staging dir path so `run_routine` reads from there.
    - Actually simpler: just mutate the routine.json text_to_type fields in place before the run, then restore after. But that's risky.
    - Simplest: Modify the step dicts in memory, write to a temp file, run from temp, delete temp. Use `tempfile.TemporaryDirectory`.

    Final approach for cli/output.py:
    ```python
    def prepare_run(routine_dir: Path, params: dict[str, str]) -> Path:
        """Prepare a routine for execution with resolved variables.

        Creates a temporary copy with variable values injected into
        text_to_type fields. Returns path to the temp directory.
        Caller is responsible for cleanup.
        """
    ```
    - Copy routine_dir to a `tempfile.mkdtemp()` directory.
    - Load routine from the copy.
    - For each step with `input_spec.type == "variable"`: strip `{}` from value to get var_name, look up in params, set `step["text_to_type"] = params[var_name]`.
    - Save routine back to the temp copy.
    - Return temp directory path.

    **Wire cli/app.py run command:**

    Update the `run_command` function:
    - After resolving routine path, call `collect_variables(path, parse_params(param))` to get full params.
    - If params has any entries, call `prepare_run(path, params)` to get a temp dir, then call `run_routine(temp_dir)`. Clean up temp dir after.
    - If no params needed, call `run_routine(path)` directly.
    - After run completes, print a Rich Panel summary: "Routine completed" (green) or "Routine failed" (red) with step count and duration from RunResult.

    Update the `record` command:
    - Ensure `show_loading_screen()` is called FIRST as the sequential gate.
    - Then `minimize_terminal()`.
    - Then lazy-import and call `cmd_record(name)`.
    - Then `restore_terminal()`.
    - Print summary.

    Update the `update` command similarly with loading screen gate.

    **Wire cli/tui.py run_tui handoff:**

    Update `run_tui()` to ensure proper sequential handoff:
    - `show_loading_screen()` runs first (Rich Live context exits cleanly).
    - Menu loop: `_show_menu()` returns command.
    - For each command that launches Qt (record, run, update):
      1. `minimize_terminal()` from `cli._minimize`
      2. Lazy-import the Qt-dependent function INSIDE the if-block
      3. Call the function
      4. `restore_terminal()` from `cli._minimize`
      5. Print completion summary with Rich Console
      6. Loop back to menu
    - For non-Qt commands (list, inspect, fork, delete): execute directly, loop back to menu.
    - "quit" breaks the loop.

    **Update main.py for backward compatibility:**

    Replace the entire content of `main.py` with a thin redirect:
    ```python
    """OCSD entry point -- redirects to cli.app:main.

    This file exists for backward compatibility. The primary entry
    point is now ``cli.app:main`` registered via ``[project.scripts]``
    in ``pyproject.toml``.
    """
    from __future__ import annotations

    import sys


    def main() -> int:
        """Redirect to the Typer CLI entry point."""
        from cli.app import main as cli_main
        cli_main()
        return 0


    if __name__ == "__main__":
        sys.exit(main())
    ```
