### Partial Requirements

#### RUN-09: Step-by-step replay status visible to user

- **REQUIREMENTS.md:** `[x]` Complete
- **VERIFICATION.md (Phase 7):** passed
- **Integration Check:** PARTIAL — `ReplayOverlayAdapter` class is complete and tested, but never instantiated in CLI `run_command()`, TUI run dispatch, or API `_run_in_thread()`. All three call `run_routine()` without passing the adapter as `callback=`.
- **Impact:** Visual replay overlay (purple shimmer, StatusBadge, TargetHighlight, CameraFlash) never activates during actual routine execution. Replay runs headless with no visual feedback.

#### SEC-01: Hub scanner flags suspicious patterns

- **REQUIREMENTS.md:** `[x]` Complete
- **VERIFICATION.md (Phase 10):** passed
- **Integration Check:** PARTIAL — `hub/scanner.py::scan_skill()` exists and the test verifies it returns `ScanResult`. However, it is never called at runtime before executing any routine. Additionally, `scan_skill` accepts legacy `skill_data` dict with `nodes`/`edges` keys, not the v1 `routine` format with `steps`.
- **Impact:** No routine is actually scanned for suspicious patterns before execution. The scanner is test-verified for existence only.

## Integration Gaps

### Gap 1: ReplayOverlayAdapter not wired (HIGH)

| Path | Location | Issue |
|------|----------|-------|
| CLI run | `cli/app.py:155` | `run_routine(routine_dir=run_path)` — no callback, no QApplication |
| TUI run | `cli/tui.py:370` | `run_routine(routine_dir=routine_path)` — no callback |
| API run | `api/server.py:366-375` | Uses `_make_run_callback` (RunManager only) — acceptable for headless |

**Fix:** CLI and TUI run paths need `QApplication` + `OverlayController` + `ReplayOverlayAdapter`, passed as `callback=` to `run_routine()`.

### Gap 2: Scanner not called at runtime (LOW)

| Path | Location | Issue |
|------|----------|-------|
| All run paths | `runner.py`, `api/server.py` | `scan_skill()` never invoked before routine execution |
| Schema mismatch | `hub/scanner.py` | Accepts `skill_data` dict, not v1 `routine` format |

**Fix:** Add `scan_routine()` wrapper that adapts v1 routine format → scanner input, call from `run_routine()` preflight or API endpoint.
